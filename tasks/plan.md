# План перехода NEXUS AU на терминал

База: ветка `feat/nexus-core-architecture`, ee4e88ed563c5f9d45bf5d24442b51b1b4094f76. Цель — основной продукт как CLI-агент для работы в каталоге проекта, подобный Claude Code. Это план, а не утверждение о готовности. Исходная ветка содержит React/Tauri, TypeScript-ядро и тесты; `nexusRuntime.ts` зависит от browser/Tauri, а `workspaceTools.ts` — от Tauri IPC. Graphify на момент исследования индексировал main, поэтому выводы о ветке сделаны по её файлам.

## Архитектурное направление

Предлагается Node.js CLI на TypeScript, чтобы повторно использовать независимые контракты и логику `src/core`. Реальную пригодность каждого модуля проверить до переноса. Выделить порты модели, хранилища, разрешений и файловой системы; реализовать терминальные адаптеры. Не имитировать безопасность Rust-host обычными проверками строк: сохранить или заменить защищённую реализацию с доказанными свойствами. Провайдеры и реальные ключи не подключать до отдельного этапа интеграции владельца, согласно docs/CONTRIBUTING.md. Точный провайдер, распространение и перенос данных остаются открытыми решениями.

Последовательность: инвентаризация → минимальный CLI и поддельная модель → защищённые инструменты и агентный цикл → сохранение данных и остальные функции → проверка → развитие Desktop на общем с CLI движке. Существующие функции удалять только после документирования их терминальной замены или явного решения об исключении; голос, изображения и Training Lab требуют отдельного определения терминальных сценариев.

## Распределение плагинов

- **Graphify:** карта связей и тестов, когда индекс охватывает текущую ветку; до этого локальный код — источник истины.
- **Agent Reach:** первичные документации CLI и платформ через доступные источники; проверять версии и ссылки.
- **Agent Skills:** границы модулей, безопасность, миграция, тесты и разбивка задач.
- **Matt Pocock Skills:** исследование и ревью границ, диагностика сложных дефектов.
- **Superpowers:** проработка дизайна, планирование и проверка готовности.
- **Ponytail:** проверка простоты и удаление ненужных абстракций после реализации.
- **Cloud Environment:** сборка и проверки в рабочей среде, фиксация недоступных платформ.
- **GitHub:** состояние ветки и CI, при необходимости PR; не сливать без разрешения.
- **Vercel:** аудит того, что станет ненужным при уходе от веб-продукта; не развёртывать и не удалять ресурсы автоматически.
- **Notion:** при наличии релевантных источников — прочитать требования; запись только по отдельной необходимости и в согласованное место.
- **UI UX Designer, Impeccable, Product Design:** проектирование терминальных сценариев, читаемости, управления с клавиатуры и доступности; визуальные веб-процессы не подменяют проверку настоящего терминала.
- **Plugin Management:** проверка доступности и прав перечисленных интеграций, без изменения настроек.

## Контрольные точки

После каждого этапа запускать соответствующие тесты и проверять реальные сценарии. Сохранить Desktop, перенести его на общий с CLI Agent Engine и обеспечить совместимость существующих данных. Перед завершением проверить Linux, macOS и Windows в CI и вручную проверить хотя бы один реальный терминал; недоступные проверки отметить отдельно. Запуск существующих полных frontend тестов и сборки обязателен, пока они остаются в проекте. Живые провайдеры проверяются только на этапе интеграции владельцем.

## Риски и открытые вопросы

- Безопасность файлов и команд: текущий Rust-хост содержит защиту от гонок и перехода по ссылкам; CLI обязан сохранить проверяемые гарантии.
- Совместимость существующих хранилищ, учётных данных и истории: определить формат и миграцию после инвентаризации.
- Удаление Tauri может затронуть vault, SQLite и native-команды; сначала найти замены и проверить их на всех платформах.
- Провайдер и модель не выбраны; локальные тесты использовать с контролируемым тестовым адаптером, не выдавая его за рабочую модель.
- Нужны решения о терминальных аналогах мультимодальности, мобильного доступа и обучения, а также о способе установки.

## Сверка реализации на 863285b (2026-11-17)

- Desktop: `src/lib/nexusRuntime.ts` собирает общие `src/core` planner/workflow, model router, gateway, memory, knowledge, projects и checkpoints; browser использует localStorage, Tauri — native repositories и IPC. `src/lib/workspaceTools.ts` обращается к Tauri; `src-tauri/src/workspace_fs.rs` использует закреплённые каталоги и no-follow при проходе компонентов. Наличие кода и тестов не подтверждает ручную работу Desktop или платформенные гарантии в этой среде.
- CLI: `cli/nexus.ts` использует `ModelRouter`, `AgentPlanner`, `PlanExecutor`, `ToolGateway` и `TerminalSession`; до текущего изменения провайдеров и инструментов нет, audit намеренно отказывает. CLI не подключает Desktop memory, checkpoint, MCP, workspace и хранилища. `TerminalSession` — отдельный управляющий состоянием диалога слой, а не доказательство полноценного агентного цикла.
- Повторно пригодны контракты и логика `src/core/model.ts`, `agentPlanner.ts`, `agentWorkflow.ts`, `planExecutor.ts`, `tools.ts`, `toolRegistry.ts`, `memory.ts`, `knowledge.ts`, `mcpClient.ts` и репозиторные интерфейсы; для работающего CLI нужны host-адаптеры и проверка совместимости данных. Desktop conversation schema отличается от терминальной истории: миграция не реализована.
- Отсутствующие CLI-адаптеры: защищённый workspace, долговечные audit/checkpoint, совместимые memory/knowledge/projects, MCP transport и конфигурация моделей. Node API с проверкой строки или `realpath` до `open` не защищает от подмены компонентов. Предпочтительный путь — выделить защищённый Rust workspace в переиспользуемую библиотеку и предоставить CLI ограниченный локальный интерфейс, затем проверить Linux/macOS/Windows, включая гонки. До этого файловый доступ закрыт.
- Проверка исходной базы: `npm test` и `npm run build` прошли после установки без install-скриптов; стандартная установка ONNX не удалась из-за сетевого отказа. Rust/Cargo отсутствуют; нативная сборка и CI по ОС не подтверждены.

## Workspace CLI и совместимость данных (2026-11-17)

- `workspace_fs.rs` соединяет Tauri `State<WorkspaceAccess>`, persistent grants и файловые операции; `workspace_fs_search.rs` реализует отдельный ограниченный content search. Безопасный путь — выделить capability-логику и grants в библиотеку, оставив Tauri команды тонкими обёртками, и использовать её в отдельном локальном CLI-процессе. Node не должен выполнять файловые операции как fallback.
- Предлагаемый IPC: один доверенный исполняемый файл, запускаемый без shell; ограниченные versioned JSON-сообщения по stdin/stdout, отдельный процесс на операцию или отдельная команда отмены с гарантированным завершением; stdout только протокол, ограничение bytes и timeout. Root предоставляется явным действием владельца, backend самостоятельно подтверждает grant, закрепляет корень и проверяет каждый компонент с no-follow. Разрешены только list/read/search, без write и shell; размер файла, глубина обхода, число файлов и результатов ограничиваются на native стороне. Клиент проверяет размер и схему ответа; ошибки не раскрывают содержимое вне grant. Закрепление доверенного пути бинарника и защита от подмены — обязательные условия до подключения.
- `cli/workspace.ts` — только контракт/адаптер Gateway; production backend и IPC ещё не реализованы. Проверки с подставным backend проверяют только управление потоком и разрешения, не симлинки или гонки ОС. Нужны native интеграционные тесты с реальными ссылками, подменой каталогов, лимитами, отменой и проверка Windows/macOS/Linux.
- CLI история (`cli/history.ts`): JSON `{version:1,messages:[{role,content}]}`, нешифрованный файл, без идентификаторов, времён, проектов и вложений. Desktop: SQLite `nexus-au.sqlite`, таблицы conversations/messages с id, project_id, timestamps, source references и image attachment (схема изменялась миграциями), projects, memory_records/knowledge_chunks, checkpoints и audit/trace. Browser: `nexus-au:conversations:v2` и legacy v1, с переносом в SQLite при Tauri; memory в `nexus-au:memory:v1` или native SQLite. Provider settings находятся в `nexus-au:provider:v1`, MCP в `nexus-au:mcp-servers:v1`, секреты управляются native vault; список разрешённых каталогов сохраняется отдельно от SQLite.
- Прямое объединение CLI JSON и Desktop невозможно без потери метаданных. Возможный импорт — только отдельная проверенная транзакционная операция с резервной копией, новыми стабильными ID, явным владельцем проекта и тестами повторного запуска/повреждений/вложений; нельзя приписывать отсутствующие timestamps или автоматически переносить разрешения и ключи. Миграция не выполнялась.
